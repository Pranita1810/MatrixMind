MODULE 01

Docker Fundamentals 🐳 Images · Containers · Dockerfile · Volumes · 1.5 hrs

1.1 What is Docker?

Docker packages your app + its environment into a container — a portable, isolated unit that runs identically everywhere.

TermMeaning
ImageBlueprint / snapshot (like a class definition)
ContainerRunning instance of an image (like an object)
DockerfileRecipe / instructions to build an image
RegistryRemote store for images (Docker Hub, ECR, GCR)
LayerEach Dockerfile instruction creates a cached layer

1.2 Install Docker

bash
# Ubuntu/Debian
sudo apt-get update && sudo apt-get install docker.io -y
sudo systemctl start docker
sudo usermod -aG docker $USER   # run without sudo (re-login)

# macOS
brew install --cask docker

# Verify
docker --version
docker run hello-world

1.3 Your First Dockerfile

app.py

python
from flask import Flask, jsonify, request

app = Flask(__name__)
tasks = []

@app.route("/tasks", methods=["GET"])
def get_tasks():
    return jsonify(tasks)

@app.route("/tasks", methods=["POST"])
def add_task():
    task = request.json
    tasks.append(task)
    return jsonify(task), 201

@app.route("/health")
def health():
    return jsonify({"status": "ok"})

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

Dockerfile

dockerfile
# Always use specific tags, not :latest
FROM python:3.11-slim

WORKDIR /app

# Copy deps first — leverages layer cache
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .
EXPOSE 5000
CMD ["python", "app.py"]

Build & Run

bash
docker build -t task-api:v1 .
docker run -p 5000:5000 task-api:v1
curl http://localhost:5000/tasks

1.5 Dockerfile Best Practices

dockerfile
# ✅ Specific tag — never :latest in production
FROM python:3.11-slim

# ✅ Layer caching — deps BEFORE code
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .      # code changes don't bust pip cache

# ✅ Non-root user for security
RUN adduser --disabled-password appuser
USER appuser

# ✅ Explicit entrypoint
ENTRYPOINT ["python"]
CMD ["app.py"]
⚠️Always create .dockerignore — exclude __pycache__, .git, *.pyc, .env, venv/

1.6 Volumes & Networks

bash
# Named Volume — persists after container dies
docker volume create mydata
docker run -v mydata:/app/data task-api:v1

# Bind Mount — local dir hot-reloaded (dev)
docker run -v $(pwd):/app task-api:v1

# Custom Network — containers talk by hostname
docker network create mynet
docker run --network mynet --name api task-api:v1
docker run --network mynet --name db postgres:15
# "api" reaches "db" by hostname "db"

2.1 Multi-Stage Builds

Produce lean production images by separating the build environment from the runtime environment.

dockerfile
# Stage 1: heavy builder
FROM python:3.11 AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --user -r requirements.txt

# Stage 2: lean production image
FROM python:3.11-slim
WORKDIR /app
COPY --from=builder /root/.local /root/.local
COPY . .
ENV PATH=/root/.local/bin:$PATH
CMD ["python", "app.py"]
✅Multi-stage can shrink images from ~1GB → ~100MB. Run docker images after to compare.

2.2 Docker Compose

api/app.py (with Redis)

python
from flask import Flask, jsonify, request
import redis, json, os

app = Flask(__name__)
r = redis.Redis(host=os.getenv("REDIS_HOST", "redis"), port=6379)

@app.route("/tasks", methods=["GET"])
def get_tasks():
    tasks = r.lrange("tasks", 0, -1)
    return jsonify([json.loads(t) for t in tasks])

@app.route("/tasks", methods=["POST"])
def add_task():
    task = request.json
    r.rpush("tasks", json.dumps(task))
    return jsonify(task), 201

docker-compose.yml

yaml
version: "3.9"

services:
  api:
    build: ./api
    ports:
      - "5000:5000"
    environment:
      - REDIS_HOST=redis
    depends_on:
      - redis
    restart: unless-stopped
    volumes:
      - ./api:/app     # dev hot reload

  worker:
    build: ./worker
    environment:
      - REDIS_HOST=redis
    depends_on:
      - redis
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    volumes:
      - redis_data:/data

volumes:
  redis_data:

3.1 What is Kubernetes?

Kubernetes orchestrates containers at scale — scheduling, self-healing, load balancing, and rolling updates automatically.

ObjectRole
PodSmallest unit — 1+ containers sharing network & storage
DeploymentManages Pods — rolling updates, replicas, self-healing
ServiceStable network endpoint to reach a set of Pods
ConfigMapNon-secret configuration as key-value pairs
SecretSensitive data (base64-encoded)
NamespaceLogical cluster isolation (dev/staging/prod)
IngressHTTP/HTTPS routing to Services
PVCPersistent storage claim for stateful workloads

3.3 Deployment YAML

yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: task-api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: task-api
  template:
    metadata:
      labels:
        app: task-api
    spec:
      containers:
      - name: task-api
        image: yourusername/task-api:v1
        ports:
        - containerPort: 5000
        resources:
          requests:
            memory: "64Mi"
            cpu: "100m"
          limits:
            memory: "128Mi"
            cpu: "200m"
        livenessProbe:
          httpGet:
            path: /health
            port: 5000
          initialDelaySeconds: 10
        readinessProbe:
          httpGet:
            path: /health
            port: 5000
          initialDelaySeconds: 5

4.4 StatefulSet for Redis

yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis
spec:
  serviceName: redis-service
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
      - name: redis
        image: redis:7-alpine
        command: ["redis-server", "--appendonly", "yes"]
        volumeMounts:
        - name: redis-data
          mountPath: /data
  volumeClaimTemplates:   # auto PVC per pod
  - metadata:
      name: redis-data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 1Gi

5.2 CI/CD with GitHub Actions

yaml — .github/workflows/deploy.yml
name: Build & Deploy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3

    - name: Docker Login
      uses: docker/login-action@v2
      with:
        username: ${{ secrets.DOCKER_USERNAME }}
        password: ${{ secrets.DOCKER_TOKEN }}

    - name: Build & Push
      uses: docker/build-push-action@v4
      with:
        context: ./api
        push: true
        tags: ${{ secrets.DOCKER_USERNAME }}/task-api:${{ github.sha }}

    - name: Deploy to K8s
      run: |
        kubectl set image deployment/task-api \
          task-api=${{ secrets.DOCKER_USERNAME }}/task-api:${{ github.sha }} \
          -n taskapp

5.3 🐛 Debugging Guide

PendingProblem 1: Pod stuck in Pending
bash
kubectl describe pod <pod> -n taskapp
# Read "Events:" section — will show the reason

kubectl get events -n taskapp --sort-by='.lastTimestamp'
kubectl describe node minikube       # check free resources
kubectl get pvc -n taskapp           # check if PVC is Bound

Common causes: Insufficient CPU/memory → reduce resource requests. PVC not bound. No schedulable nodes.

CrashLoopBackOffProblem 2: Pod keeps crashing
bash
kubectl logs <pod> -n taskapp --previous  # crashed container logs ← key!
kubectl describe pod <pod> -n taskapp

# Exit codes:
#   1   = app error (check Python traceback in logs)
#   137 = OOMKilled → increase memory limits
#   143 = SIGTERM (graceful shutdown)

kubectl edit deployment task-api -n taskapp
# Increase limits.memory: 128Mi → 256Mi for OOMKilled
Service ErrorProblem 3: Service not reachable
bash
# Endpoints MUST show pod IPs — empty = label mismatch!
kubectl get endpoints task-api-service -n taskapp
kubectl get pods -n taskapp --show-labels

# Test from inside cluster
kubectl run test --image=busybox -it --rm -- \
  wget -qO- http://task-api-service.taskapp.svc.cluster.local/health

Fix: Ensure spec.template.metadata.labels.app in Deployment matches spec.selector.app in Service.

ImagePullBackOffProblem 4: Cannot pull image
bash
kubectl describe pod <pod> -n taskapp
# Events will show: Failed to pull image...

# Fix: create registry secret
kubectl create secret docker-registry regcred \
  --docker-username=USER --docker-password=PASS \
  --docker-email=EMAIL -n taskapp

# Add to deployment spec.template.spec:
# imagePullSecrets:
# - name: regcred
Readiness FailedProblem 5: Pod not receiving traffic
bash
kubectl describe pod <pod> -n taskapp
# Look for: Readiness probe failed

# Test the probe endpoint directly
kubectl exec -it <pod> -n taskapp -- curl localhost:5000/health

# Fix: increase initialDelaySeconds, or fix /health endpoint

5.5 Production Checklist

  • ✅Specific image tags — never :latest in production
  • ✅.dockerignore in every project
  • ✅Non-root USER in Dockerfile
  • ✅Multi-stage builds for lean images
  • ✅Resource requests AND limits on every container
  • ✅Liveness + Readiness probes on all pods
  • ✅Rolling update strategy configured
  • ✅HPA for variable workloads
  • ✅Secrets via K8s Secret objects, not ConfigMap
  • ✅RBAC — least privilege principle
  • ✅Namespace per environment (dev/staging/prod)
  • ✅Image tagged with git SHA in CI/CD, not :latest
