MODULE 01 · 30 MIN

Airflow Architecture & Core Concepts

What Airflow is · Why it exists · Every component explained

Apache Airflow is an open-source platform to programmatically author, schedule, and monitor workflows. It was created at Airbnb in 2014 and donated to the Apache Software Foundation in 2016. Today it powers data pipelines at thousands of companies.

Mental Model Think of Airflow as a highly intelligent cron job manager that understands task dependencies, retries failures, sends alerts, and gives you a beautiful UI to observe everything.

The Six Core Components

⚙️
Scheduler
Heart of Airflow. Reads DAG files, triggers task instances when dependencies are met. Runs continuously.
🌐
Web Server
Flask-based UI. Lets you trigger, monitor, inspect logs, and configure connections/variables.
🗄️
Metadata DB
PostgreSQL or MySQL. Stores DAG runs, task instances, logs, connections, variables, and users.
👷
Executor
Decides HOW tasks run. Local, Sequential, Celery, Kubernetes, or Dask executor.
🔁
Worker
Process (or pod) that actually executes the task code. Multiple workers = parallelism.
📬
Triggerer
New in 2.2. Async process for deferrable operators — no worker slot wasted while waiting.

Architecture Flow Diagram

Flow DAG File → Scheduler parses → Creates DagRun → Creates TaskInstances → Executor queues tasks → Workers execute → Results stored in Metadata DB → Web UI shows status.

Key Terminology

TermDefinition
DAGDirected Acyclic Graph — a collection of tasks with defined dependencies
DAG RunA specific execution instance of a DAG for a logical_date
TaskA definition of a unit of work (the class/operator)
Task InstanceA specific run of a Task within a DAG Run
logical_datePreviously execution_date — the date the DAG "thinks" it's running for
data_intervalThe time window the DAG is processing
XComCross-communication — how tasks share small data
VariableKey-value pair stored in metadata DB, accessible anywhere
ConnectionNamed credential/connection info for external systems
PoolLimits concurrency of certain tasks (e.g., max 5 DB queries at once)
HookInterface to external service (wraps connection logic)
SensorSpecial operator that waits for a condition to be true

Task Instance States

  • scheduled — Scheduler has identified this task should run
  • queued — Submitted to executor, waiting for a worker slot
  • running — Worker is actively executing the task
  • success — Task completed without error
  • failed — Task raised an exception
  • up_for_retry — Failed but has retries remaining
  • upstream_failed — A dependency failed (propagated failure)
  • skipped — Branching logic chose another path
  • deferred — Async deferral waiting for trigger condition

DAGs — Deep Dive

DAG anatomy · Dependencies · Dynamic DAGs · Best practices

Anatomy of a DAG File

PYTHON
from datetime import datetime, timedelta
from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.operators.bash import BashOperator

# ── Default args apply to ALL tasks unless overridden ──
default_args = {
    'owner': 'data-team',
    'depends_on_past': False,   # don't wait for previous run's success
    'start_date': datetime(2024, 1, 1),
    'email': ['team@company.com'],
    'email_on_failure': True,
    'email_on_retry': False,
    'retries': 3,
    'retry_delay': timedelta(minutes=5),
    'retry_exponential_backoff': True,  # 5, 10, 20 min delays
    'max_retry_delay': timedelta(minutes=60),
    'execution_timeout': timedelta(hours=2),  # kill task after 2h
}

# ── DAG Definition ──
with DAG(
    dag_id='example_dag',
    description='A complete example DAG',
    schedule='@daily',              # cron expression or preset
    start_date=datetime(2024, 1, 1),
    end_date=None,                    # optional: stop scheduling after this date
    catchup=False,                    # don't run historical backfill on first deploy
    max_active_runs=1,               # only 1 DAG run at a time
    max_active_tasks=10,             # max concurrent tasks across all runs
    default_args=default_args,
    tags=['etl', 'production'],      # UI tags for filtering
    doc_md="""
    ## Example DAG
    This DAG does X, Y, Z.
    """,
) as dag:

    start = BashOperator(
        task_id='start',
        bash_command='echo "Pipeline starting"',
    )

    process = PythonOperator(
        task_id='process',
        python_callable=lambda: print("processing"),
    )

    end = BashOperator(
        task_id='end',
        bash_command='echo "Done"',
    )

    # ── Dependency Syntax ──
    start >> process >> end         # bitshift operator (most common)
    # OR: start.set_downstream(process)
    # OR: process.set_upstream(start)

Dependency Patterns

PYTHON
# Linear chain
a >> b >> c >> d

# Fan-out (a runs b and c in parallel)
a >> [b, c]

# Fan-in (b and c must both complete before d)
[b, c] >> d

# Diamond pattern
a >> [b, c] >> d

# Complex dependencies
extract >> [transform_a, transform_b, transform_c]
transform_a >> load_a
transform_b >> load_b
transform_c >> load_c
[load_a, load_b, load_c] >> notify

ExpressionMeaning
@onceRun exactly once
@hourlyEvery hour
@dailyOnce a day at midnight
@weeklyOnce a week (Sunday midnight)
@monthlyFirst day of every month
0 6 * * *Every day at 6:00 AM UTC

Dynamic DAGs

PYTHON
# Pattern 1: Generate DAGs from a config list
TABLES = ['users', 'orders', 'products', 'payments']

for table in TABLES:
    with DAG(
        dag_id=f'sync_{table}',
        schedule='@daily',
        start_date=datetime(2024, 1, 1),
        catchup=False,
    ) as dag:
        extract = PythonOperator(
            task_id=f'extract_{table}',
            python_callable=extract_table,
            op_kwargs={'table': table},
        )
        load = PythonOperator(
            task_id=f'load_{table}',
            python_callable=load_table,
            op_kwargs={'table': table},
        )
        extract >> load
    globals()[f'dag_{table}'] = dag  # REQUIRED: register in globals

# Pattern 2: Dynamic tasks within a DAG (expand)
from airflow.decorators import dag, task

@dag(schedule='@daily', start_date=datetime(2024,1,1), catchup=False)
def dynamic_tasks_dag():

    @task
    def get_tables():
        return ['users', 'orders', 'products']

    @task
    def process_table(table: str):
        print(f"Processing {table}")

    tables = get_tables()
    process_table.expand(table=tables)  # Dynamic task mapping (Airflow 2.3+)

dynamic_tasks_dag()

DAG Best Practices

  • Always set catchup=False unless you need historical backfill
  • Keep DAG files lightweight — no heavy imports at the top level
  • Use max_active_runs=1 for DAGs with external dependencies
  • Set execution_timeout on every task to prevent zombie tasks
  • Use tags for UI filtering in large installations
  • Document your DAG with doc_md — it renders in the UI
  • Never use mutable global state in DAG files (it causes parsing issues)
  • Keep task functions in separate modules, import in DAG file

XCom — Cross-Communication

XComs allow tasks to share small pieces of data. They're stored in the metadata database, so keep them small (< 48KB). For large data, store in S3/GCS and pass the path via XCom.

PYTHON
# Push XCom (from callable)
def extract(ti, **context):
    data = fetch_from_api()
    # Method 1: return value (auto-pushed as 'return_value')
    return data

    # Method 2: explicit push with custom key
    ti.xcom_push(key='row_count', value=5000)
    ti.xcom_push(key='s3_path', value='s3://bucket/data.parquet')

# Pull XCom (from callable)
def transform(ti, **context):
    # Pull return_value from 'extract' task
    data = ti.xcom_pull(task_ids='extract')

    # Pull named key
    count = ti.xcom_pull(task_ids='extract', key='row_count')

    # Pull from multiple tasks
    counts = ti.xcom_pull(task_ids=['extract_a', 'extract_b'], key='count')

# Pull XCom in templates (Jinja)
run_cmd = BashOperator(
    task_id='use_xcom',
    bash_command='echo "Path: {{ ti.xcom_pull(task_ids=\'extract\', key=\'s3_path\') }}"',
)

TaskFlow API — Modern Python DAGs

PYTHON
from airflow.decorators import dag, task
from datetime import datetime

@dag(
    dag_id='taskflow_etl',
    schedule='@daily',
    start_date=datetime(2024, 1, 1),
    catchup=False,
    tags=['taskflow'],
)
def etl_pipeline():

    @task(retries=3, retry_delay=timedelta(minutes=5))
    def extract() -> dict:
        # Return value automatically becomes XCom
        return {'rows': 1000, 'source': 'postgres'}

    @task
    def transform(raw_data: dict) -> list:
        # raw_data is automatically pulled from XCom
        records = process(raw_data['rows'])
        return records

    @task(pool='db_pool')  # use a pool to limit DB connections
    def load(records: list) -> int:
        inserted = insert_to_db(records)
        return inserted

    @task(trigger_rule='all_done')  # run even if upstream failed
    def notify(row_count: int):
        send_slack(f"Loaded {row_count} rows")

    # Dependencies inferred from data flow!
    raw = extract()
    transformed = transform(raw)
    count = load(transformed)
    notify(count)

etl_pipeline()  # Instantiate the DAG

Trigger Rules

trigger_ruleRun when...
all_successAll upstream tasks succeeded (default)
all_failedAll upstream tasks failed
all_doneAll upstream tasks finished (any state)
one_successAt least one upstream succeeded
one_failedAt least one upstream failed
none_failedNo upstream failed (success or skipped OK)
none_skippedNo upstream skipped
alwaysAlways run, regardless of upstream state

Connections

Connections store credentials securely in the metadata DB (encrypted with Fernet). Set them via UI (Admin → Connections), CLI, or environment variables.

BASH

    --conn-type 'postgres' \
    --conn-host 'db.company.com' \
    --conn-port '5432' \
    --conn-login 'etl_user' \
    --conn-password 'secret123' \
    --conn-schema 'warehouse'

from airflow.hooks.base import BaseHook
import requests

class MyAPIHook(BaseHook):
    conn_name_attr = 'my_api_conn_id'
    default_conn_name = 'my_api_default'
    conn_type = 'http'
    hook_name = 'My Custom API'

    def __init__(self, conn_id: str = default_conn_name):
        super().__init__()
        self.conn_id = conn_id
        self._conn = None
        self.base_url = None

    def get_conn(self):
        if self._conn is None:
            conn = self.get_connection(self.conn_id)
            self.base_url = f"https://{conn.host}"
            self._session = requests.Session()
            self._session.headers.update({
                'Authorization': f'Bearer {conn.password}'
            })
        return self._session

    def get_data(self, endpoint: str, params: dict = None):
        session = self.get_conn()
        response = session.get(f"{self.base_url}{endpoint}", params=params)
        response.raise_for_status()
        return response.json()

from datetime import datetime, timedelta
from airflow.decorators import dag, task
from airflow.providers.postgres.hooks.postgres import PostgresHook
from airflow.providers.postgres.operators.postgres import PostgresOperator
from airflow.providers.slack.operators.slack_webhook import SlackWebhookOperator
from airflow.operators.python import BranchPythonOperator
from airflow.models import Variable
import pandas as pd
import logging

logger = logging.getLogger(__name__)

def on_failure_alert(context):
    """Global failure callback — send Slack alert"""
    task_id = context['task_instance'].task_id
    dag_id = context['task_instance'].dag_id
    log_url = context['task_instance'].log_url
    exception = context.get('exception')
    message = (
        f":red_circle: *Task Failed*\n"
        f"DAG: `{dag_id}`\nTask: `{task_id}`\n"
        f"Error: `{str(exception)[:200]}`\n"
        f"<{log_url}|View Logs>"
    )
    # Use SlackWebhookHook directly in callback
    from airflow.providers.slack.hooks.slack_webhook import SlackWebhookHook
    hook = SlackWebhookHook(slack_webhook_conn_id='slack_data_alerts')
    hook.send(text=message, channel='#data-alerts')


@dag(
    dag_id='ecommerce_daily_pipeline',
    description='Daily E-Commerce ETL: Extract → Validate → Transform → Load → Report',
    schedule='0 6 * * *',          # 6 AM UTC daily
    start_date=datetime(2024, 1, 1),
    catchup=False,
    max_active_runs=1,
    default_args={
        'owner': 'data-platform',
        'retries': 2,
        'retry_delay': timedelta(minutes=5),
        'execution_timeout': timedelta(hours=1),
        'on_failure_callback': on_failure_alert,
    },
    tags=['ecommerce', 'production', 'etl'],
)
def ecommerce_pipeline():

    # ── STEP 1: EXTRACT ─────────────────────────────────────

    @task(retries=3)
    def extract_orders(ds: str) -> dict:
        """Extract orders for the given date from operational DB"""
        hook = PostgresHook(postgres_conn_id='postgres_operational')
        df = hook.get_pandas_df("""
            SELECT
                o.id AS order_id,
                o.customer_id,
                o.status,
                o.total_amount,
                o.created_at,
                o.updated_at,
                o.shipping_address_id,
                COUNT(oi.id) AS item_count,
                SUM(oi.quantity * oi.unit_price) AS gross_amount
            FROM orders o
            LEFT JOIN order_items oi ON o.id = oi.order_id
            WHERE DATE(o.created_at) = %(run_date)s
            GROUP BY o.id, o.customer_id, o.status,
                     o.total_amount, o.created_at, o.updated_at, o.shipping_address_id
        """, parameters={'run_date': ds})

        logger.info(f"Extracted {len(df)} orders for {ds}")
        # Save to staging (avoid XCom size limits)
        staging_path = f"/tmp/orders_{ds}.parquet"
        df.to_parquet(staging_path, index=False)
        return {'path': staging_path, 'row_count': len(df)}

    @task(retries=3)
    def extract_customers(ds: str) -> str:
        hook = PostgresHook(postgres_conn_id='postgres_operational')
        df = hook.get_pandas_df("""
            SELECT c.id, c.email, c.segment, c.country,
                   c.first_order_date, c.lifetime_value
            FROM customers c
            WHERE c.updated_at::date >= %(run_date)s - INTERVAL '7 days'
        """, parameters={'run_date': ds})
        path = f"/tmp/customers_{ds}.parquet"
        df.to_parquet(path, index=False)
        return path

    # ── STEP 2: DATA QUALITY ────────────────────────────────

    @task
    def validate_orders(extract_result: dict, ds: str) -> bool:
        """Run data quality checks on extracted orders"""
        df = pd.read_parquet(extract_result['path'])
        errors = []

        # Check 1: Row count threshold
        min_rows = int(Variable.get('min_daily_orders', default_var='10'))
        if len(df) < min_rows:
            errors.append(f"Only {len(df)} orders, expected >= {min_rows}")

        # Check 2: No null order IDs
        null_ids = df['order_id'].isna().sum()
        if null_ids > 0:
            errors.append(f"{null_ids} orders with NULL id")

        # Check 3: Amounts are positive
        neg_amounts = (df['total_amount'] < 0).sum()
        if neg_amounts > 0:
            errors.append(f"{neg_amounts} orders with negative amount")

        # Check 4: Valid status values
        valid_statuses = {'pending', 'confirmed', 'shipped', 'delivered', 'cancelled'}
        invalid = df[~df['status'].isin(valid_statuses)]['status'].unique()
        if len(invalid) > 0:
            errors.append(f"Invalid statuses: {list(invalid)}")

        if errors:
            raise ValueError(f"Data quality failed for {ds}:\n" + "\n".join(errors))

        logger.info(f"All quality checks passed for {len(df)} orders")
        return True

    # ── STEP 3: TRANSFORM ───────────────────────────────────

    @task
    def transform_daily_revenue(orders_result: dict, customers_path: str, ds: str) -> str:
        """Build daily revenue fact table with customer dimensions"""
        orders_df = pd.read_parquet(orders_result['path'])
        customers_df = pd.read_parquet(customers_path)

        # Join orders with customer dimension
        merged = orders_df.merge(
            customers_df[['id', 'segment', 'country']],
            left_on='customer_id', right_on='id', how='left'
        )

        # Business logic transformations
        merged['revenue_net'] = merged['total_amount'] * 0.85  # after 15% platform fee
        merged['is_high_value'] = merged['total_amount'] >= 500
        merged['run_date'] = ds

        # Aggregated daily summary
        summary = merged.groupby(['status', 'segment', 'country']).agg(
            order_count=('order_id', 'count'),
            total_revenue=('total_amount', 'sum'),
            net_revenue=('revenue_net', 'sum'),
            avg_order_value=('total_amount', 'mean'),
        ).reset_index()

        output_path = f"/tmp/revenue_summary_{ds}.parquet"
        summary.to_parquet(output_path, index=False)
        logger.info(f"Transformed {len(summary)} summary rows")
        return output_path

    # ── STEP 4: LOAD ────────────────────────────────────────

    @task(pool='warehouse_pool')
    def load_to_warehouse(summary_path: str, ds: str) -> dict:
        """Upsert daily revenue summary to data warehouse"""
        df = pd.read_parquet(summary_path)
        hook = PostgresHook(postgres_conn_id='postgres_warehouse')

        # Delete existing data for this date (idempotent load)
        hook.run(
            "DELETE FROM warehouse.daily_revenue WHERE run_date = %s",
            parameters=[ds]
        )

        # Bulk insert
        hook.insert_rows(
            table='warehouse.daily_revenue',
            rows=df.values.tolist(),
            target_fields=df.columns.tolist(),
            commit_every=500,
        )

        total_revenue = df['total_revenue'].sum()
        order_count = df['order_count'].sum()
        logger.info(f"Loaded {len(df)} rows. Revenue: ${total_revenue:,.2f}")
        return {
            'rows_loaded': len(df),
            'total_revenue': float(total_revenue),
            'order_count': int(order_count),
        }

    # ── STEP 5: NOTIFY ──────────────────────────────────────

    @task(trigger_rule='all_success')
    def send_success_notification(load_result: dict, ds: str):
        """Send Slack summary of completed pipeline run"""
        from airflow.providers.slack.hooks.slack_webhook import SlackWebhookHook
        hook = SlackWebhookHook(slack_webhook_conn_id='slack_data_alerts')
        hook.send(
            text=(
                f":large_green_circle: *E-Commerce Pipeline Complete* — `{ds}`\n"
                f">📦 Orders: *{load_result['order_count']:,}*\n"
                f">💰 Revenue: *${load_result['total_revenue']:,.2f}*\n"
                f">📊 Rows Loaded: *{load_result['rows_loaded']:,}*"
            ),
            channel='#data-reports',
        )

    # ── WIRE IT TOGETHER ────────────────────────────────────
    # TaskFlow infers dependencies from data passing

    orders_result = extract_orders()
    customers_path = extract_customers()

    valid = validate_orders(orders_result)

    summary_path = transform_daily_revenue(orders_result, customers_path)
    summary_path.set_upstream(valid)  # wait for validation to pass

    load_result = load_to_warehouse(summary_path)
    send_success_notification(load_result)


ecommerce_pipeline()
